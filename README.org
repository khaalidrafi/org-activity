#+title: org-activity — an ActivityWatch alternative that writes Org
#+subtitle: Activity tracking for Emacs on Linux and Android

* What it is

org-activity tracks where your time goes and journals it as plain
Org files you own.  It is a cross-platform, Emacs-native alternative
to ActivityWatch: the same package runs on a Linux desktop and on
Android (org.gnu.emacs app or Termux), with no daemon, no database
and no network.  Three modules, one story:

| Module                     | Covers                                    | Where          |
|----------------------------+-------------------------------------------+----------------|
| =org-activity.el=          | live tracking into Org CLOCK data         | Linux, Android |
| =org-activity-linux.el=    | the system foreground window (not just    | Linux desktop  |
|                            | Emacs) while you work elsewhere            |                |
| =org-activity-android.el=  | device-wide per-app screen time from      | Android        |
|                            | Android's Usage Access data                |                |

* Supersedes two earlier packages

=org-activity= now owns both halves of the earlier split:

- =khaalidrafi/actlog= — the per-buffer engine into Org CLOCK data. That is
  =org-activity.el= here, same 32-function design.
- =khaalidrafi/android-usage.el= — StayFree CSV/JSON import, per-day tables
  and the dynamic block. That is =org-activity-android.el= here (a superset:
  it also writes the day dblock).

Both repositories are frozen and carry a DEPRECATED banner. Fixes and
features belong here.


* The engine (everywhere)

=M-x org-activity-mode= samples the current activity every 15 s and
credits wall time to it.  An activity is:

| You are in                         | Activity row        |
|------------------------------------+---------------------|
| a file inside a project            | =telega-org=        |
| a file with no project             | =Files:downloads=   |
| a special buffer (=*Telega*=, ...) | =Emacs:Telega=      |

Every day gets one Org file (=org-activity/2026-11-14.org=): one
entry per activity, one =CLOCK:= line per work session, a =:MODE:=
property on each entry.  Because the journal is ordinary Org clock
data, =org-clock-report=, the agenda and =org-clock-sum= all work on
it without this package loaded.

Honesty rules baked into the engine:

- Idleness (no input for =org-activity-idle-threshold=, default 3
  min) stops crediting, like a screen going off.
- A sampler gap larger than =org-activity-max-gap= (default 15 min)
  means the process was suspended or killed (common on Android) and
  is never credited -- no phantom pocket hours.
- State survives restarts; a flush every =org-activity-flush-interval=
  (default 5 min) bounds what a hard kill can lose.

| Command                      | What it does                               |
|------------------------------+--------------------------------------------|
| =M-x org-activity-mode=      | tracking on/off (global minor mode)        |
| =M-x org-activity-report=    | per-activity table for today (or any day)  |
| =M-x org-activity-open-journal= | open the day's Org file                 |
| =M-x org-activity-toggle=    | quick pause/resume                         |

* Linux: the system window source

On a desktop you do not live inside Emacs.  Load the module and flip
one option:

#+begin_src emacs-lisp
  (require 'org-activity-linux)
  (setq org-activity-source-function #'org-activity-linux-source)
#+end_src

While any other application is focused, the engine journals
=System:<app>= rows (window title as the entry's mode) -- the
aw-watcher-window role of ActivityWatch, from Elisp.  Detectors, in
order: =hyprctl= (Hyprland), =xdotool= (X11).  When this Emacs is
the focused app the source defers to the default so buffers, not
"Emacs", get credited.  Plain Wayland has no universal active-window
API; there the module degrades honestly to Emacs-side tracking.

* Android: device-wide screen time

Device-wide per-app usage, read NATIVELY — the complete StayFree /
ActivityWatch question answered inside Emacs:

- *Native (no export step, no third-party app)*: the stock
  =org.gnu.emacs= app already declares
  =android.permission.PACKAGE_USAGE_STATS= in its manifest; it just
  ships no code that queries it.  The org-activity patch series
  (see =NATIVE-USAGE.org=) adds the =android-usage-stats= primitive
  to the Emacs Android port.  On the patched app: grant Emacs
  "Usage access" in Android Settings, then =M-x
  org-activity-android-refresh= reads the last
  =org-activity-android-native-days= days straight from the system.
- *Fallback (stock Emacs builds)*: any app holding "Usage access"
  can export a CSV/JSON (StayFree's Settings > Backup > Export CSV
  works; any export with recognizable columns works the same way).

#+begin_src emacs-lisp
  (require 'org-activity-android)   ; optional module
#+end_src

=M-x org-activity-android-refresh= pulls through
=org-activity-android-pull-function=, whose default
=--pull-auto= prefers the native query and falls back to the newest
export in =Download/= on stock builds;
=M-x org-activity-android-import-file= imports one specific export.
Both write one table per day into =org-activity/android.org= — one
journal format, two sources.  =M-x org-activity-android-report=
shows the last-7-days StayFree-style top list with SVG charts
generated in pure Elisp.  A dynamic block does the same inside any
Org file:

#+begin_src org
,#+BEGIN: org-activity-android :days 7 :top 15 :chart t
,#+END:
#+end_src

Day tables are rewritten idempotently: re-pulling or re-importing
the same data never duplicates rows.  The engine (first section)
runs on Android too -- it is the same pure Elisp.

* Install

#+begin_src emacs-lisp
  (use-package org-activity
    :vc (:url "https://github.com/khaalidrafi/org-activity.git" :rev "PIN")
    :commands (org-activity-report org-activity-open-journal
                org-activity-toggle)
    :custom (org-activity-org-dir
             (expand-file-name "org-activity/" org-directory))
    :config (org-activity-mode +1))
#+end_src

Requires Emacs 29.1+.  No other Elisp dependencies.  The Linux
module wants =hyprctl= or =xdotool= only when enabled.

* Provenance

The engine continues =actlog= and the Android module continues
=android-usage.el= (both by the same authors); those repositories
are superseded by this package.
